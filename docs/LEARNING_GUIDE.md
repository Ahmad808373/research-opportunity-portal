# Understand and explain your project

## The three parts

The **frontend** is what you see: labels, cards, forms, and buttons. It runs in
your browser. The **backend** is Python running on your computer. It receives
requests, checks them, and performs database work. **MySQL** stores the actual
records on disk. These are three logical layers even though Flask serves both
the HTML files and the API from one address.

The browser never connects directly to MySQL and never knows its password.
It communicates with Flask; Flask communicates with MySQL.

| Step when creating an opportunity | What happens |
|---|---|
| 1. Fill the form | Browser collects title, description, area, faculty, department, skills, positions, deadline, status |
| 2. Press Save | HTML/JavaScript checks the input; Save becomes disabled while processing |
| 3. Send POST | fetch sends the data as JSON to /api/opportunities |
| 4. Validate in Python | Flask rejects missing/invalid fields with JSON and HTTP 400 |
| 5. Insert into MySQL | Connector passes a parameterized INSERT to the opportunities table |
| 6. Generate ID | MySQL AUTO_INCREMENT creates a unique integer ID |
| 7. Commit | Python tells MySQL to make this transaction permanent |
| 8. Respond | Flask returns the saved record, a message, and HTTP 201 |
| 9. Refresh | JavaScript fetches the list and details again and displays the stored data |

## What Flask is

Flask is a small Python web framework. A framework provides useful web functions
so we do not need to implement an HTTP server from scratch. Here Flask receives
HTTP requests, maps a URL and method to a Python function, reads JSON, and sends
JSON responses. It also serves index.html, CSS, and JavaScript.

In `@app.get('/api/opportunities')`, the decorator tells Flask: when a GET request
arrives for this URL, run the function below it. `app.run()` starts the local server.
The server listens on 127.0.0.1, meaning this computer, using port 5000 by default.
A port identifies a service: Flask and MySQL use different ports.

## What a REST API is

An API is a defined way for two programs to communicate. Our browser asks the
backend to perform an operation and receives a response. REST organizes this
communication around resources and HTTP methods. Our resource is an opportunity;
`/api/opportunities/7` refers to opportunity ID 7.

| Method | Simple meaning | Our example |
|---|---|---|
| GET | Read stored data | List all or retrieve ID 7 |
| POST | Create a new record | Add a new research opening |
| PUT | Change a stored record | Edit ID 7 or set its status to Closed |
| DELETE | Remove a stored record | Delete ID 7 |

This assignment uses PUT for partial changes too. Python first reads the existing
row, applies the supplied fields, and validates the complete result. A status-only
request can close the opportunity without sending all the other fields again.

## JSON and HTTP status codes

JSON is a text format for structured data. An object uses named values, such as
`{"title":"Network Study","available_positions":2}`. A list uses square brackets.
Strings have double quotes; numbers do not. JavaScript uses JSON.stringify to
convert form data into JSON text. Flask reads that JSON and returns JSON using
jsonify. JSON is the message format; MySQL is the permanent storage.

An HTTP response includes a status code as well as its body. The code tells the
client whether its request succeeded; the JSON supplies data or an explanation.

| Code | Meaning | Actual project example |
|---|---|---|
| 200 OK | Successful operation | GET, PUT, or DELETE succeeded |
| 201 Created | New resource stored | POST returned a saved opportunity and generated ID |
| 400 Bad Request | Client input was invalid | Negative positions, missing description, malformed JSON |
| 404 Not Found | Requested resource is missing | GET a deleted opportunity |
| 500 Internal Server Error | Server could not complete valid work | MySQL connection fails |

The list endpoint returns `[]` with 200 for an empty database, not 404. A valid
but missing ID returns 404. An invalid ID such as `abc` returns 400.

## How MySQL stores records

A database is a named collection of stored data. A table organizes data into rows
and columns. Each row in `opportunities` is one research opening. The columns
store the required assignment fields. The primary key `id` uniquely identifies
the row, even when two opportunities have the same title.

| SQL type/constraint | Purpose here |
|---|---|
| INT AUTO_INCREMENT PRIMARY KEY | Unique ID generated by MySQL |
| VARCHAR | Limited-length title, area, faculty, and department text |
| TEXT | Description and required skills |
| INT | Whole-number positions |
| DATE | A real deadline date rather than arbitrary text |
| ENUM('Open','Closed') | Restricts status choices |
| NOT NULL | A required column cannot be NULL |
| CHECK | Non-negative positions and non-empty text safeguards |
| InnoDB | Supports transactions and row locking |

NOT NULL alone does not prevent an empty string, so the schema also has blank-text
checks. MySQL 8.0.16+ is required because the CHECK constraints must be enforced.
Backend validation supplies helpful messages before the database rejects bad data.

Stopping Flask does not delete database files. Restarting MySQL also keeps its
stored data. Running schema.sql again does not erase the table. Copying the source
code to another computer does not automatically copy the stored records.

## How Python connects to MySQL

`mysql-connector-python` is the driver: a Python library that communicates using
MySQL's database protocol. `get_connection()` reads DB_HOST, DB_PORT, DB_USER,
DB_PASSWORD, and DB_NAME from local environment configuration.

The `.env` file contains your computer's settings. python-dotenv loads it. Its
password stays on the backend and is not sent to the browser or committed.
`.env.example` contains placeholders so another person can configure their own
computer. Existing environment variables take precedence over the .env file.

A **connection** is the communication session with MySQL. A **cursor** executes
SQL and reads results. A dictionary cursor returns column names with their values,
making them easy to convert to JSON. Flask's `g` holds the current request's
connection. The teardown function closes it after the response, including on errors.

`cursor.execute('SELECT * FROM opportunities WHERE id = %s', (id,))` supplies the
ID separately from the SQL. The connector treats it as data, so malicious SQL-like
text cannot turn into an executable SQL command. `%s` is the connector's parameter
placeholder; it is not an instruction to format the SQL using Python `%`.

`commit()` saves a transaction. Without committing a mutation, its change would
not become permanent. A transaction groups work so it can succeed together or
roll back. PUT uses `SELECT ... FOR UPDATE` to lock its target during the update,
preventing another simultaneous update from changing that row midway through.
After the request, an unfinished transaction is discarded when the connection closes.

## How frontend functions work

`fetch()` sends a network request. It does not automatically treat a 400/404/500
as a JavaScript failure, so our `api()` helper checks response.ok and displays the
backend's error. A timeout prevents an indefinitely waiting request.

The browser obtains opportunities from GET requests. The JavaScript array is only
a current display copy of API results; it is not the database. Refreshing or reopening
the page retrieves MySQL data again. Nothing is preloaded as pretend research data.

HTML required/min/step attributes catch missing fields and invalid positions.
JavaScript also rejects spaces-only strings, converts the positions input to a
number, and prevents a second submit while busy. Server validation remains essential:
someone can bypass the form by sending a request in Postman.

We use textContent to display user text. A description containing `<script>` appears
as text rather than running a script in the browser. The delete confirmation protects
against accidental clicking. A failed save leaves form values intact for retrying.

## Likely questions and short answers

| Instructor question | Your answer |
|---|---|
| Why Flask? | It gives us a small Python web server and simple routes for this assignment. |
| Where is the data? | In MySQL's opportunities table, not in a JavaScript array permanently. |
| Why an ID if titles exist? | Titles can repeat; the generated ID uniquely identifies each record. |
| What is CRUD? | Create, Read, Update, Delete. |
| Why POST instead of GET to create? | POST changes stored state; GET is for reading it. |
| Why 201 on create? | It tells the client a new resource was stored successfully. |
| Why is an empty list 200? | The read succeeded; there are simply no rows. |
| What if the ID does not exist? | A valid missing ID returns 404 with a JSON error. |
| How do you close an opportunity? | PUT to its ID with status Closed, then refresh the saved data. |
| How is partial PUT supported? | Merge supplied fields into the stored record and validate before updating. |
| Why validate twice? | The frontend helps users; the backend prevents invalid direct API requests. |
| What stops SQL injection? | Parameterized queries keep user values separate from SQL commands. |
| What does commit do? | It makes a successful database change permanent. |
| Why zero positions allowed? | The requirement says non-negative; zero is non-negative. |
| Why no login? | The assignment does not require it, so the project stays simple. |
| Why no CORS dependency? | Flask serves frontend and API from the same origin. |
| What happens if MySQL stops? | The API returns a safe 500 and the frontend displays an error. |
| What happens if Flask stops? | An already open page shows a connection error on API actions. A new page cannot load until Flask runs. |
| Are screenshots proof of all tests? | No; our test report also has executed API, collection, and browser results. |
| Did you run Postman desktop here? | No. Its exported collection was executed using Newman; I demonstrate desktop Postman locally. |
